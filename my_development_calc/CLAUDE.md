# my_development_calc — контекст проекта

## Назначение

Расчётно-оптимизационный модуль для подбора оптимальной застройки участка. На вход — параметры участка и ограничения. На выход — ранжированный список сценариев застройки с финансовыми метриками и сравнительными графиками.

**Главный вопрос, на который отвечает модуль:** какой из вариантов застройки выгоднее и насколько (в процентах от лидера)?

Уровень точности — preliminary feasibility (±15–25%). Это инструмент для отсева вариантов на ранней стадии, не сметный расчёт.

## Ключевое архитектурное решение: условные единицы

Модуль работает в **условных единицах**, а не в рублях. Это сознательный выбор:

- Для сравнения вариантов важны соотношения, а не абсолютные числа
- Не нужно зависеть от справочников НЦС, индексов Минстроя, обновлений цен
- Модель проще, быстрее в разработке, легче калибруется

**Базовая единица:** 1.0 = условная стоимость м² типового жилья 9-этажного монолита со стандартной отделкой. Все остальные стоимости и цены — относительно этого.

Переход к рублям возможен в будущем (см. дорожную карту v0.3).

## Регион и нормативы

Стартовый регион — **Санкт-Петербург**. Используются нормативы РНГП СПб и СП 42.13330. Структура конфигов поддерживает добавление других регионов.

## Стек

- Python 3.11+
- `pydantic` — модели и валидация YAML
- `numpy`, `numpy-financial` — финансовые метрики
- `pandas` — табличные данные и CSV-выгрузки
- `matplotlib` (обязательно) + `plotly` (опционально для интерактива) — графики
- `jinja2` — HTML-отчёт
- `pyyaml` — конфиги
- `pytest` — тесты

## Точки расширения

- **Новый тип объекта:** добавить значение в `BuildingType`, заполнить его удельную стоимость и параметры в `unit_costs.yaml`, при необходимости — нормативы в `norms.yaml`
- **Новый регион:** добавить блок в `norms.yaml` с региональными нормативами и ценами продажи
- **Новый коэффициент:** добавить в `coefficients.yaml` и применить в `cost.py`
- **Переход к рублям:** ввести параметр `unit_to_rub_multiplier` в `settings.yaml`, применять в финальной агрегации (см. v0.3)

## Что модуль НЕ учитывает (упрощения)

- НДС
- Кредитное финансирование и стоимость денег во времени (NPV считается, но без учёта стоимости капитала проекта)
- Фазирование строительства (всё единым проектом; расширение — v0.4)
- Штрафы по ДДУ, страхование, маркетинг
- Налоговые льготы и инвестиционные соглашения
- Реалистичные cash flow с S-кривой освоения (по умолчанию равномерное распределение)

Эти ограничения зафиксированы здесь намеренно, чтобы при будущем уточнении было понятно, куда копать.

## Дорожная карта

- **v0.1** — оценка заданных сценариев в у.е., базовый набор типов объектов, нормативы СПб, базовые графики. Цель: можно вручную задавать сценарии и сравнивать их.
- **v0.2** — генератор сценариев (автоматический подбор), Парето-фронт, чувствительность к коэффициентам, HTML-отчёт.
- **v0.3** — переход к рублям через простой множитель (грубая оценка для конкретного участка).
- **v0.4** — НЦС-интеграция (опционально, по флагу), фазирование, кредитное финансирование, Monte Carlo по неопределённости.

## Калибровочные значения (стартовые)

Полный набор значений — в `src/config/unit_costs.yaml`. Логика их выбора зафиксирована в SPEC.md, секция «Стартовые коэффициенты».

## Принципы кода

- Type hints везде
- Чистые функции там, где это естественно (расчёты)
- Все денежные значения в у.е., в коде везде явное упоминание единиц
- Параметры — только в YAML, ничего не хардкодить
- Все промежуточные значения расчёта возвращаются в структурах `*Breakdown` для прозрачности и аудита
- Логирование через `logging` (DEBUG для промежуточных значений)
